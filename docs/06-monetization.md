# 収益化

買い切り課金1本と、バナー広告。購入者には広告を出さない。

| 項目 | 内容 |
|---|---|
| 商品 | 非消耗型（買い切り）1つ。商品ID `kakeibo_pro_unlock` |
| 価格 | ¥500（実際の表示価格はストアから取得する） |
| 解放されるもの | 貯金機能 / 広告の非表示 |
| 広告 | AdMob のバナーのみ。ホームと履歴の最下部 |
| 実装 | `expo-iap`（Apple / Google と直接）、`react-native-google-mobile-ads` |

## 構成

```
app/pro.tsx                    課金の案内・購入・復元
src/services/purchases.ts      ストアとのやり取り（商品取得・購入・所持確認）
src/services/ads.ts            広告SDKの初期化と ATT
src/stores/useEntitlement.ts   所持状態。端末に控えを持つ
src/components/AdBanner.tsx    バナー。購入者には何も描かない
```

## 設計判断

### RevenueCat を使わず直接つないでいる

このアプリは「データを外部に送信しない」ことを設計の前提にしているので、
購入情報のためだけに第三者のサーバーを経由させたくない。

商品が非消耗型1つだけなら、仲介の利点（サブスクの状態管理、
クロスプラットフォームの名寄せ、分析）がほとんど効かない。
iOS は StoreKit 2 が端末内で署名検証済みの取引を返し、
Android は Play から購入一覧を取得して照合すれば足りる。

### 検証サーバーを持たない

サーバーが無い以上、端末側で細工すれば突破はできる。
¥500 の機能解放に対して検証サーバーを建てて運用する価値はないと判断している。
本気で守る必要が出たら、そのときに RevenueCat か自前の検証を足す。

### 所持状態は端末に控える

`settings.pro_unlocked` に持つ。起動直後はこの値で描き、
そのあとストアに問い合わせて上書きする。

**控えは「購入済み」を保つ方向にしか使わない。**
ストアが明確に「未購入」と答えたときだけ false にする。
通信できないだけで機能を取り上げると、返金でもないのに
「買ったのに使えない」という最悪の体験になる。

### 未購入でも貯金の枠は見せる

記録画面の種別トグルから貯金を隠さず、鍵アイコンを出して
押したら課金画面へ送る。存在ごと隠すと、何が買えるのか分からない。

保険として画面側でも `isPro` を見ている（`app/savings/index.tsx`)。
導線をすり抜けて直接来られても開かない。

### 広告は失敗したら消す

読み込みに失敗したときは高さごと消す。空の枠が残ると壊れて見えるため。
購入者には SDK の初期化ごと省いている。

## 出す前にやること

### 1. 商品を登録する

**App Store Connect**
- 「App内課金」→ 非消耗型 → 商品ID `kakeibo_pro_unlock`
- 価格を ¥500 に設定
- 審査用のスクリーンショットと説明が必要（課金画面を撮る）
- **商品を作るだけでは審査に回らない。** バージョンのページで
  課金商品を選び、ビルドと一緒に提出すること。
  これを忘れると Guideline 2.1(b) で差し戻され、
  審査環境で商品が取れないため購入画面もエラーになる
  （→ [10-rejection-2.1ab.md](./10-rejection-2.1ab.md)）
- **税務・銀行情報の登録を済ませないと商品が「準備完了」にならず、
  アプリの審査ごと落ちる**

**Play Console**
- 「アプリ内アイテム」→ 商品ID `kakeibo_pro_unlock` → ¥500 → 有効化
- 商品IDは両ストアで揃える（`src/services/purchases.ts` の `PRODUCT_ID`）

### 2. AdMob を設定する

AdMob では **iOS と Android が別アプリ**として登録される。
それぞれにアプリIDと広告ユニットIDが発行されるので、最終的に4つのIDが要る。

IDは2種類あり、**区切り文字だけが違う**。前半（発行元の16桁）は共通なので
目視では取り違えやすい。

| ID | 形 | 置き場所 |
|---|---|---|
| アプリID | `ca-app-pub-<16桁>` **`~`** `<10桁>` | `app.json` のプラグイン設定 `iosAppId` / `androidAppId` |
| 広告ユニットID | `ca-app-pub-<16桁>` **`/`** `<10桁>` | `app.json` の `extra.admobBannerIos` / `admobBannerAndroid` |

取り違えたときの症状が重い。

- アプリIDが不正 → **iOS は起動直後にクラッシュする**（`GADApplicationIdentifier` の検証に落ちる）
- ユニットIDが未設定 → 本番なのにテスト広告が出て**収益がゼロになる**

どちらもストアに出してから気づくことになるので、提出前に必ず検査する。

```bash
npm run check:ads
```

### IDを .env に置かない理由

AdMob のIDは**秘密情報ではない**。アプリのバイナリに埋め込まれ、誰でも取り出せる。

一方 `.env` は gitignore されるため、別の環境でクローンしたときに黙って欠落する。
その状態でビルドすると、エラーも警告も出ないまま**本番ビルドにテスト広告が載る**。
バージョン管理下（`app.json`）に置いて、欠けていれば検査で気づけるようにしてある。

### 現在の状態

| 項目 | 値 |
|---|---|
| iOS アプリID | 設定済み |
| iOS バナー | 設定済み |
| Android アプリID | **Google のテスト用ID**（未登録のため。形式が不正だと起動しないので0埋めは使えない） |
| Android バナー | 未設定 |

**Android を公開する前に、AdMob で Android アプリを登録して差し替えること。**
`npm run check:ads` が警告し続ける。

**本番IDのまま自分で広告をタップすると規約違反でアカウントが止まる**ので、
動作確認はテスト広告のままで行うこと。

### 3. プライバシー関連を書き直す

広告を入れた時点で「データを外部に送信しない」は成り立たなくなる。
以下をすべて更新すること（→ [05-release.md](./05-release.md)）。

- プライバシーポリシー（広告配信のための識別子の利用を明記）
- Apple のプライバシーマニフェスト（`app.json` の `ios.privacyManifests`）
- Play のデータセーフティ申告
- `SKAdNetworkItems`（AdMob のプラグインが自動で入れる）

家計簿の中身（取引・予算・貯金）は従来どおり端末内にしか無い。
外に出るのは広告SDKが扱う識別子だけなので、
説明ではその線引きを明確に書くこと。

### 4. 審査で落ちやすい点

| 指摘 | 対策 |
|---|---|
| 「購入を復元」が無い | `app/pro.tsx` に実装済み。**消さないこと** |
| 課金の内容が不明瞭 | 課金画面に「買い切り」「解放される機能」を明記済み |
| 商品が取得できない | 税務・銀行情報の未登録が原因のことが多い |
| ATT を文脈なく出す | 起動処理の最後、画面が見えたあとに出している |
| 外部決済への誘導 | 一切入れていない（規約違反） |

## テスト

課金は実機でしか試せない。Expo Go では動かない（→ [04-development.md](./04-development.md)）。

- **iOS**: App Store Connect で Sandbox テスターを作り、端末の
  「設定 → App Store → SANDBOX アカウント」でサインインする
- **Android**: Play Console の「ライセンステスト」にアカウントを追加し、
  内部テストトラックに配信する

購入は Sandbox なら課金されない。復元も同じ経路で試せる。
