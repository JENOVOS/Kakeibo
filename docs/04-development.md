# 開発手順

## 前提

- Node.js 20 以上（動作確認: v24.20.0）
- 実機（iPhone / Android）またはエミュレータ
- Mac は不要（iOS ビルドは EAS のクラウド Mac で行う）

## セットアップ

```bash
npm install
```

> `.npmrc` に `legacy-peer-deps=true` を入れてある。`expo-router` が web 用に引き込む
> `react-dom` と `react` のバージョン指定が食い違うためで、ネイティブビルドには影響しない。

## 開発サーバーの起動

```bash
npx expo start
```

表示される QR コードを読み込むと実機で確認できる。

### Expo Go では動かない

**課金（`expo-iap`）と広告（`react-native-google-mobile-ads`）を入れた時点で、
Expo Go では起動しなくなった。** どちらも Expo Go に同梱されていないネイティブモジュール。

以降の開発はすべて**開発ビルド**で行う（→ 次節）。
`expo-dev-client` は導入済み。

その代わり Expo Go 互換のための **SDK 54 固定は不要になった**。
上げるかどうかは別途判断する（→ [技術スタック](./02-tech-stack.md#sdk-バージョンの方針)）。

## 開発ビルド（development build）

Expo Go の代わりになる、このプロジェクト専用のクライアント。
SDK のバージョンに縛られず、通知も本番と同じ挙動になる。

`eas.json` の `development` プロファイルと `expo-dev-client` は導入済み。

```bash
npm install -g eas-cli
eas login                          # Expo アカウントでログイン（対話式）
```

### Android（無料）

```bash
npx eas build --profile development --platform android
```

ビルドが終わると APK のダウンロード URL と QR コードが出る。
端末で読み込んでインストールすれば完了。Google Play の開発者登録は不要。

### iOS 実機（Apple Developer Program が必要）

実機にインストールするには署名が要るため、**$99/年の Apple Developer Program** が必須。
（無料の Apple ID では EAS からの実機向けビルドはできない）

```bash
npx eas device:create          # 端末の UDID を登録（QR からプロファイルを入れる）
npx eas build --profile development --platform ios
```

### 起動

どちらの場合も、インストール後は Expo Go ではなく
**入れた開発ビルドのアプリ**を開いてから開発サーバーに接続する。

```bash
npx expo start --dev-client
```

ネイティブモジュールを追加・削除したときだけ、開発ビルドを作り直す必要がある。
JS の変更だけならビルドし直さずそのまま反映される。

## よく使うコマンド

| コマンド | 内容 |
|---|---|
| `npx expo start` | 開発サーバー起動 |
| `npm test` | domain 層のテスト（12件） |
| `npm run lint` | 型チェック（`tsc --noEmit`） |
| `npm run db:generate` | `schema.ts` からマイグレーション生成 |
| `npm run check:ads` | AdMob のID設定を検査（提出前に必ず） |
| `npm run shots` | ストア用スクリーンショットを実寸PNGで書き出す |
| `npx expo export --platform android` | バンドルが通るか確認（実機不要） |
| `npx expo install --check` | SDK に対して古い/新しい依存を検出 |

### 依存を追加するとき

```bash
npx expo install <パッケージ名>   # ネイティブモジュール（必ずこちら）
npm install <パッケージ名>        # 純粋な JS ライブラリ
```

`npx expo install` は SDK バージョンに適合する版を選ぶ。
ネイティブモジュールに `npm install` を使うとバージョン不整合でビルドが壊れる。

## テスト

```bash
npm test
```

対象は `src/domain/` の純粋関数。DB にも React にも依存しないため、
エミュレータなしで即座に回る。

カバーしている範囲:

- 金額のパース（全角数字・カンマ・円記号・小数の切り捨て・不正入力）
- 金額の書式化（符号付き表示、0除算の回避）
- 月の範囲（月末、うるう年、年またぎ）
- 固定費の日付計算
  - 毎月N日、毎年M月N日、毎週W曜
  - **毎月31日の月末丸め**（2月28日/29日、4月30日）と、丸めた翌月に31日へ戻ること
  - 開始日より前に発生しないこと
  - 終了日を過ぎたら `null` を返すこと
  - 1年ぶん連続で前進させて12回になること

固定費の日付計算はバグが「気づかないうちに二重計上／計上漏れ」として現れ、
ユーザーが気づきにくい。ここだけはテストを維持する価値がある。

### テストを追加する

`tests/*.test.ts` に置けば `npm test` が拾う。
`@/` のパスエイリアスがそのまま使える（tsx が `tsconfig.json` を読む）。

## 動作確認のポイント

エミュレータでは再現しづらく、見落としやすい箇所。

| 確認項目 | 方法 |
|---|---|
| 固定費の自動計上 | 端末の日付を進めてアプリを再起動する |
| 長期間の未起動 | `next_due_on` を数ヶ月前にして起動し、まとめて計上されるか |
| 月末の固定費 | 毎月31日で登録し、2月・4月をまたぐか |
| バックアップ復元 | 書き出し → 全消去 → 復元 で件数が一致するか |
| ダークモード | OS 側で切り替え、予算バーの色が判別できるか |
| 日付ピッカー | 年の送りボタンで前後の年に1タップで移動できるか |
| 固定費の日選択 | 毎月/毎年/毎週それぞれで日・曜日・月が選べるか（過去にここが潰れる不具合があった） |
| 入力中のカテゴリ追加 | 記録画面の「追加」から作り、そのまま選択状態になるか |
| モーダル内のダイアログ | 記録・固定費・カテゴリ編集の各画面で、日付／カテゴリ追加／日選択のダイアログが**手前に**出るか（過去に背面へ隠れる不具合があった） |
| タブバー | 中央の ＋ から記録画面が開くか、最後の項目がバーに隠れていないか |
| 貯金 | 目標を作り、記録画面の「貯金」枠から積み立てて、ホームのリングと達成率が動くか |
| 貯金の集計 | 貯金を記録したら「全体の支出」「収支」「全体予算の消化」に反映されること。カテゴリ別予算には入らず「予算未設定の支出」に出ること |
| 貯金の分類表示 | 履歴・固定費一覧で「未分類」ではなく「貯金・（目標名）」と出ること |
| テーマ | 端末をダークにしてもアプリはライトのまま。設定から切り替えると反映されるか |
| 課金 | Sandbox / ライセンステストで購入 → 貯金が開き広告が消えるか。**アプリを消して入れ直し「購入を復元」で戻るか** |
| 未購入の見え方 | 貯金トグルに鍵が出て課金画面へ飛ぶか。設定の「貯金の目標」も同様か |
| 広告 | テスト広告が出るか。購入後に高さごと消えるか |
| 数値書体 | 金額が Manrope（等幅）で表示され、桁が揃っているか |
| ダークモードの下地 | OS をダークにして全画面を開き、白背景のまま残る画面がないか |
| キーボードの取り回し | 記録画面で金額入力中（キーボードが出た状態）に日付を押し、キーボードが閉じてカレンダーの決定ボタンまで押せるか |
| 固定費のまとめて追加 | 期間と規則を指定して件数プレビューが合うか、確認ダイアログを経て履歴に入るか |
| 日本語入力 | カテゴリ名・固定費名・メモで、**トグル入力（同じキーの連打で か→き→く と送る）**が正しく送りになるか。文字が増えていったら制御入力に戻ってしまっている |
| 通知 | 開発ビルドで、`notify_days_before` を当日にして時刻を過ぎさせる |

## 既知の注意点

### プロジェクトのフォルダ名に日本語が入っている

`create-expo-app` はプロジェクト名に URL セーフな文字しか許さないため、
このフォルダ内で直接スキャフォールドすることはできない。
すでに構築済みなので通常の開発には影響しないが、**別プロジェクトを新規作成する場合は
英数字のフォルダ名で作ってから中身を移すこと。**

`app.json` の `slug` は `kakeibo`（英数字）になっており、EAS 側はこれを使う。

### `babel.config.js` を消さないこと

Expo SDK 54 以降、通常は `babel.config.js` が不要になった。
このプロジェクトでは Drizzle のマイグレーション `.sql` を JS から import するために
`babel-plugin-inline-import` が必要で、そのために残している。
消すと起動時にマイグレーションが読めずクラッシュする。

同じ理由で `metro.config.js` の `sourceExts.push('sql')` も必須。

### バンドル ID は変更しないこと

`com.jenovos.kakeibo`。App Store Connect に登録済みのIDと一致させてある。
**一度ストアに登録すると変更できない**ので、書き換えるとビルドを受け付けなくなる。
